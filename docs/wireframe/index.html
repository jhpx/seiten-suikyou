页面关系

全站三个页面，同一时刻只显示一个；切换页面时全局框架保持不动。首页负责找人，明细页看单个角色，模拟页做装备假设。任何页面都要能回到上一页。

贯穿全站的支路

  • 顶栏切换语言后，当前页面内容整体换成对应语言，筛选与选中状态保留。
  • 顶栏刷新会重新取一次账号数据；成功给出完成提示，失败给出友好错误说明。
  • 分享链接可以直接定位到某个角色的明细页，不必先经过首页。
  • 每个页面都有加载中、失败、无数据三种状态，位置与对应内容区一致。

版式规范

  • 单一基准宽度，任何设备上看到的都是同一张版面，只是倍率不同。
  • 顶栏固定在画布之外，不参与画布内部的缩放。
  • 内容高度变化后要重新匹配外框高度，避免底部留一段空白。
  • 圆角、描边、间距统一走第 09 节的设计规格。

状态编码

在线 / 断线不能只靠颜色区分：同时给形状标记（✓ / ✕ / ○）和底色，文字只保留区服名。错误提示常驻，成功与提示自动收起。

交互规则

  • 视图切换是单颗循环按钮，只显示「当前是哪个」，点一下换下一个；不做左右分段，方便以后加第三种视图。
  • 按钮外观按性质区分：状态按钮用实心胶囊，打开浮层的按钮用方角，一眼能分出「点了就换」和「点了要选」。
  • 筛选 / 排序只更新角色网格那块，工具条本身保持不变，避免展开态和选中态被打断。
  • 建议卡用原生折叠行为；缺件要显式标出，不能留空白让用户猜。

信息层级

角色名与分数是第一层，档位与武器/套装信息是第二层，统计数字是第三层。工具条的说明文字比按钮再弱一级，不抢首屏注意力。

浮层规范

  • 结构固定：标题 / 内容 / 底部操作。主按钮只有一个，放最右；「清空」在无选中时隐藏。
  • 已选数量用角标报个数，不在按钮上写长句，避免把图标挤变形。
  • 筛选维度内是「或」、维度之间是「且」，这句规则要在浮层里可见。
  • 草稿态：取消 / 关闭一律丢弃，不产生任何页面变化。

状态与文案

  • 成功与提示数秒后自动收起，错误常驻直到下一次操作。
  • 失败只给用户能看懂的友好说明，不展示原始技术错误。
  • 空状态要说清「现在是什么情况 + 下一步能做什么」。
  • 关键信息不依赖悬停；触屏没有稳定的悬停行为。可点区域不小于 44px。

阅读顺序

装备 → 这把尺子怎么量（新板块）→ 实际打多少（伤害表）。新板块里的伤害是随流派与配置变的推导量，下面那张表是固定真值；把固定值压在最后当锚，逻辑才顺。

版式规范

  • 左侧评分卡与右侧网格等高，底缘落在同一行；高低差会看起来像多出一截。
  • 长文案要能收进固定宽度，宁可缩字号也不要溢出到隔壁卡片。
  • 同组字号必须一起降档，不能出现「词条小、汇总大」这种半套压缩。
  • 整张画布导出为图片，所有新增区块都会进图，加高前先想清楚代价。

状态

伤害与增益内容就绪前显示骨架占位，失败给一行说明，无数据时不出表；三种状态都占同样的位置，避免页面跳动。

信息层级决策

  • 只保留一个「基准词条」汇总值，不再另设表尾合计行 —— 同一屏出现两个相同合计是重复。
  • 不显示极限分、达成率与极限基准列；这些指标口径偏粗，展示出来会误导对比。
  • 同屏只出现一套分数，避免两个来源不同、数值接近的分数互相打架。
  • 三个汇总值同排一行，方便横向比较：你的总量 / 参与计分的量 / 尺子的基准。

列设计理由

  • 其中武器：武器贡献单独列，与「你的」是包含关系，表头必须写明「其中」，否则会被当成要相加的另一份来源。没有贡献时画破折号，不写 0.0。
  • 基准：显示配平后的值，才与用户在外面看到的读数一致；原始值只用弱化小字标在暴击 / 爆伤两行。
  • 不设「配平 / 不配平」两列：配平只是把词条在双爆之间搬动，合计不变，两列并列会出现两个一样的合计；而且只有两行的数字会变，其余全等。
  • 「你的」保持原样：评分用的是真实面板，展示一个「假如重分双爆」的假设值会混淆读数。
  • 只有 4 项有基准可对照，其余属性合成一行「未计入」，不铺空格；以后多了含充能的流派，行数自然增加。

视觉与交互

  • 用中性蓝，不碰现有评分的金色档位色；不出现档位字母，避免读成「另一套评级」。
  • 流派切换即时换数据、不重新加载整页；切换后重新匹配画布高度。
  • 右下只写规则归属与「仅供参考与娱乐」，不写任何计算公式 —— 这套规则是闭源的。
  • 弱化小字在深色卡底上要保证至少 4.5:1 对比度；辅助信息也不能只靠颜色区分。
  • 设计稿里的数值一律示意；实现时数值保持全精度，只在最外层展示时统一保留 1 位小数。

版式规范

  • 顺序固定：返回栏 → 角色头 → 属性对照 → 装备清单 → 伤害对比。

表单规则

  • 全部使用原生选择控件，选项文字由业务数据提供，界面不自带一份名称表。
  • 主词条固定的部位显示只读文本，不摆一个点了没反应的空下拉。
  • 副词条行数有上限，不足时用空行补齐，保证各卡片对齐。
  • 改过的装备卡要有明确标记，并能单件或整体还原。

浮层规范

沿用第 03 节：同一时刻一个浮层、草稿态提交、主按钮唯一且放最右。确认后只更新受影响的内容区，不整页重画。

这份稿子的用法

它只回答三个问题：长什么样（区块、层级、尺寸、颜色）、怎么点（入口、出口、浮层、状态流转）、什么状态（加载、失败、空、成功）。结构标签、模块划分、接口、数据字段与文件位置都不在本稿范围内，由实现方案自行决定。线框内的角色、名称与数字全部是示意内容，不代表任何真实数据。

09

设计规格

全站共用的一套视觉令牌。实现时可以按技术习惯换算单位，但呈现结果要与这里一致。

字号与字重

  • 页面主标题 24 / 分节标题 17 / 区块标题 13 / 正文 13 / 辅助 11（px）
  • 大数字 22–26，仅用于评分与汇总
  • 字重只用常规与中等两档；不靠加粗制造层级，靠字号与颜色
  • 表格数值统一右对齐、统一保留 1 位小数

间距与形状

  • 基准 4px，常用 8 / 12 / 16 / 24
  • 控件圆角 6px、卡片 10px、胶囊 20px
  • 描边 1px 中性色；不用渐变、不用彩色投影
  • 区块之间靠 1px 暗缝分隔，不叠边框

颜色

  • 中性 4 级：底 / 面 / 抬升面 / 文字，正文用最深一级
  • 蓝：新板块、可点状态、当前视图
  • 琥珀：当前状态标记、待实现标记
  • 绿 / 红只用于成功与错误，不用于装饰
  • 档位配色自成一套，YSIN 板块不复用

可访问性

  • 正文对比度 ≥ 4.5:1，大字 ≥ 3:1
  • 状态不只靠颜色：同时给形状或文字标记
  • 可点区域不小于 44px；关键信息不依赖悬停
  • 纯图标按钮要有可读名称，图标本身要能表意
  • 弱化小字也要过对比度门槛，不能淡到看不清
