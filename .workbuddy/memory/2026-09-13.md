用户反馈「画的太简易」，于是把 `profile-detail` 的 DOM/CSS 当规格书重写。

- **规格来源**：miao 的模板不在 npm 包里，在 GitHub
  `yoimiya-kokomi/miao-plugin/resources/character/profile-detail.{html,css}`（另有
  `artis-mark` / `profile-stat` / `character-card` / `avatar-list`）。国内要挂代理
  `curl --proxy socks5h://127.0.0.1:4080` 拉。本地 `miao-plugin/` 克隆里**没有**这些模板。
- **结构**（逐节照抄）：
  `.basic` 立绘 + 角色名/`UID - Lv.N`/N命 + 天赋 a/e/q + 面板属性表 `.char-attr`
  （图标位+名称+权重+数值）+ 命座 6 格 + 数据时间；

- **单条「分」公式**：miao 是 `46.6/6/100 * _mark` = `46.6*_mark/600`，后端 shape.js 算好成
  `point` 字段发给前端（前端不再自己算）。
- **词条标题有两套表，别混用**（踩过坑）：
  - 圣遗物主/副词条用 `Artifact.getArtisKeyTitle('gs')` —— **区分大/小**（`hpPlus`→小生命、`atk`→大攻击）；
    i18n 表 `statName('hpPlus')` 只有「生命值」，用它就丢了大小信息。
  - 有效词条汇总再短一档：大/小生命→生命，暴击率→暴击，暴击伤害→爆伤，充能效率→充能，元素精通→精通。

  → 404 时前端显示 ⚔ 字形占位 + 名称/精N/Lv.N。

- **命座有真图**：`meta-gs/character/{名}/icons/cons-{1..6}.webp`。
- **天赋也有真图**，而且两条规则很反直觉（见 `models/character/CharImg.js:87 getImgs`）：
  1. 天赋 A 的图标 = **武器类型公共图** `common/item/atk-{sword|claymore|bow|catalyst|polearm}.webp`
     （普攻图标本来就是武器图标）。
  2. 天赋 E/Q 的图标 = **提升它的那个命座图标**（`talentCons` 里写的 3 / 5）。
     角色 `icons/` 目录下**根本没有** `talent-e.webp`，只有 `cons-1~6` 和 `passive-0~2`。
- **武器图路径**：`meta-gs/weapon/{类型}/{名}/icon.webp`，类型取自 miao 元数据
  （vendor 里 `resources/meta-gs/weapon/{类型}/data.json` 有 id→name）。

所以 `shape.js` 里照上游公式自己拼路径（`charImgs()`，纯字符串，十几行，不引新依赖）。
